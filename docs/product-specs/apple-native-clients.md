# 产品规格：Apple 原生客户端

## 1. 产品方向

TomeKeep 的正式客户端面向 macOS 与 iOS。两端使用 SwiftUI 原生实现，共享领域、持久化、网络、同步和元数据能力，并根据桌面与手机的使用场景提供不同界面。

原生双端完整交付后，Electron 桌面端与 Web PWA 停止作为产品形态维护。未来出现非 Apple 平台需求时重新评估跨平台方案，不在当前原生架构中预埋 Web 容器。

## 2. 产品目标

- 保留现有书库、愿望单、多档案、阅读状态、标签、搜索、排序、封面和价格能力。
- 保证已有 Electron 本地数据与云端数据无损迁移。
- iOS 支持 ISBN 手输、粘贴、单次扫码和连续扫码。
- macOS 与 iOS 均在本机查询和关联第三方元数据。
- macOS 保留价格抓取、Ollama 匹配、登录墙和验证码恢复。
- 两端均支持离线使用和可靠云同步。
- 界面遵循各自平台习惯，而不是复刻旧 React UI。

## 3. 平台能力

### 3.1 共享能力

- 认证、注册、退出和会话恢复。
- 书库与愿望单 CRUD。
- 愿望单移入书库。
- iOS 愿望单顶部提供独立“只看待购买”购物车筛选，可与搜索/标签组合，再点恢复全部；详细及封面视图均有可见更多菜单，提供“已购买，移入书库”、编辑、关联页面与删除。移入书库复用 Mac 原子事务：保留书目、标签、封面和关联 URL，愿望软删除，两端变更进入自动同步；重复 ISBN 拒绝且保留原愿望。成功显示短暂反馈，不将“已购买”误作阅读状态。点击书名/元数据打开已有有效 HTTP(S) 关联页面，封面保留编辑；没有关联网址时回退编辑，不伪造豆瓣链接。
- 愿望单不提供优先级编辑、排序或展示；迁移期仍原样保留旧端 priority 字段用于数据与协议兼容。
- 多档案与独立阅读状态。
- 标签、搜索、排序和筛选。
- 书库/愿望表单默认先显示已选标签，再显示无文字的“＋”；点击后在原位置展开输入框和未选候选，不提供搜索。iOS 下方原位显示“常用标签”，ISBN 与标签收起态共用 44 pt 行高基线及相同内边距；标签较多或字体放大时自然换行，不固定总高度裁切内容。候选合并两类本机记录，按使用记录数降序、同频稳定排序，过滤已选和空值，支持连续点选且不清掉未提交的手输内容。iOS 提交/完成或输入框失焦时将非空输入纳入草稿并收起，保存表单也包含未确认输入，取消整个表单不写入。候选沿用原标签配色，已选保留删除入口，图标按钮保留读屏名称；Mac 的紧凑布局及提交方式见下文。
- iOS 愿望详细列表及封面视图均提供独立待购买按钮，不进入表单；选中使用实心购物车与状态读屏反馈，可再次点击取消，保留滑动和编辑表单入口；持久化与自动同步复用原有逻辑。
- 标签“＋”与原位输入框沿用已选标签的胶囊轮廓、浅色背景和相同视觉高度，保留 44 pt 触控区；点击“＋”仅展开候选并解除其他字段焦点，不自动弹出键盘，用户点击标签输入框后才进入手输。
- 常用标签沿用现有 TagPalette 的类别色文字及浅色胶囊背景，同一标签在已选、候选和列表中的配色一致，不使用统一中性灰替代。
- Mac 的书籍/愿望卡片与表单采用桌面专属紧凑标签：22 pt 胶囊与同高实底加号、130 pt 原位输入框、240 pt 下方常用标签浮层；候选约 24 pt 高，横向 4 pt/换行 6 pt 间距。浮层不提供重复“完成/新建”区域，也不撑高卡片；Enter 提交后可继续添加，Escape 仅取消未提交输入，点击外部结束。卡片标签即时保存，表单只更新草稿；iOS 保持现有触控尺寸与交互。
- 愿望详细列表不重复显示“待购买”文字行，以购物车按钮的空心/实心状态表达，避免标记切换导致行高增加；保留按钮读屏状态。
- ISBN 校验、规范化与语义展示。
- 新增书库或愿望时可从剪贴板识别豆瓣详情 URL、ISBN 或书名；macOS 可自动检查豆瓣 URL，iOS 只在用户明确点击导入后读取剪贴板。
- 豆瓣图书 App 分享地址 `https://www.douban.com/doubanapp/dispatch/book/<id>?...`（含无 www 形式）与标准 `book.douban.com/subject/<id>/` 共用导入流程，统一为 HTTPS 详情地址并丢弃分享参数；仅识别可信域名、HTTP(S) 与数字图书 ID，不扩展为任意跳转或其他内容类型。
- 豆瓣/OpenLibrary/isbnsearch 元数据瀑布流。
- 豆瓣标题/作者搜索和候选关联。
- 封面下载、校验、缓存、上传和修复。
- 本地优先、离线 outbox 和同步修复。
- 中英文、深浅色和无障碍。

### 3.2 iOS 专属

- 摄像头 ISBN 扫描。
- 单本与连续录入。
- 扫描框选、声音和克制触觉反馈。
- 触控优先导航、Sheet 和滑动操作。

### 3.3 macOS 专属

- 原生本机采价与可见书店网页复用 WebKit 默认持久化会话，等待动态商品/价格出现并在稳定后读取；当当中文搜索沿用旧版 GBK 兼容编码。登录/风控需用户完成，不绕过验证或关闭 TLS/ATS。切换渠道/关闭窗口取消过期查询，失败不写入假价格，商品新窗口链接在现有书店视图打开，提供重新加载及脱敏错误域/代码。
- 每轮 Mac 修改通过相关验证后自动运行 `scripts/install-mac.sh`，安装为 `/Applications/TomeKeep Next.app`；原生旧包可恢复备份，保留旧 Electron `/Applications/TomeKeep.app`、用户数据及正在运行的进程，必要时提示用户重启。
- 高密度书库管理。
- 菜单命令、键盘快捷键和多窗口。
- 京东、当当、中国图书网价格抓取。
- Ollama 本地匹配与算法回退。
- 零售商与元数据网站的可见登录/验证码窗口。
- 旧 Electron 数据导入。

## 4. 数据要求

- 本地数据库是交互的第一写入目标。
- 网络失败不能导致本地业务操作丢失。
- 同步项必须持久化，应用重启后可继续。
- 已登录时，应用在启动、回到前台和登录成功后自动同步；本地业务写入成功后请求一次可合并的后续同步，不要求用户手工搬运数据。
- 正式原生客户端必须通过认证门禁：未登录、Token 缺失或服务端确认 Token 失效时，只显示登录/邀请码注册界面，不得展示书库、愿望、设置或本机数据。
- 覆盖安装可以保留系统钥匙串会话；启动时先恢复并验证该会话，验证通过后不重复要求输入密码。服务暂时不可达时，曾成功登录的设备可继续离线使用并保留待同步修改。
- 每台设备必须使用同一个 TomeKeep 账户，Xcode/Apple ID 登录不等于 TomeKeep 登录；退出登录立即返回认证门禁，但不擅自删除本机数据。
- 同步请求必须串行执行；进行中的重复请求合并为一个后续同步周期，避免并发覆盖并保证同步期间产生的修改会继续上传。
- 设置页必须显示本次运行的同步中、最近成功结果或失败原因，并保留手动重试入口。
- 同步失败须显示可操作的网络原因或响应格式错误的接口/字段，不以“本机数据未丢失”替代原因。最近失败的脱敏诊断可保存在本机设置中，成功同步或退出登录后清除，不记录令牌、响应正文或字段值。
- 旧数据中的空或无效可选关联网址不能阻断整页书籍/愿望同步；原生仅展示有效 HTTP(S) 关联链接，读取时不改写服务器原记录。
- 接收 ISO 与旧 SQLite UTC 日期；必需日期不可解析时不得静默跳过书目并推进游标。日期兼容修复后允许每账户/设备安全全量重拉一次，以 LWW 保留更新的本地修改，随后恢复增量同步。
- 云端 ID 与本地 ID 必须稳定。
- 软删除和 tombstone 必须跨设备传播。
- 封面本地缓存损坏不能破坏书籍记录。
- 云端封面采用单请求串行下载：当前可见项按当前展示顺序优先，其次当前页面筛选结果，再按添加时间降序/ID 稳定顺序补齐其余记录。滚动、切换页面和排序影响下一张，不取消当前下载；已缓存图片不删除或隐藏。每张完成立即刷新，包括相同文件名的缺失文件修复；记录已删除或封面键变化时不挂接过期下载。失败不写假文件名，后续同步重试。
- 跨设备相同 ISBN 不同 ID 的冲突方案见 `docs/design-docs/cross-device-book-conflicts.md`。连续扫码发现已存在规范 ISBN 时直接提供打开已有书籍；双离线新增产生的云端冲突进入持久候选，标签并集与空字段补齐可自动处理，非空字段、封面、阅读状态冲突逐项确认。愿望购买时若书库已有同 ISBN，明确确认后合入标签并完成愿望，不新增第二本。
- 迁移不得改变标题、作者、ISBN、出版社、标签、时间、优先级、阅读状态、详情 URL、封面关联或价格含义。

## 5. 第三方数据要求

- 原生客户端不得调用 TomeKeep 元数据代理。
- 查询只在用户明确录入、关联或修复时发起。
- 摄像头帧不得持久化或上传。
- 第三方登录凭据不得由 TomeKeep 读取或传输。
- Cookie 仅存储在应用专用网站数据存储中。
- 查询失败必须允许用户手工完成录入。
- 第三方页面结构变化不得损坏本地已有数据。

## 6. 迁移要求

- 迁移期 Electron、PWA 和原生客户端同时保持可用，但不能共享写入同一个本地目录。
- 原生预览版使用独立 Bundle ID 和数据目录。
- Electron 数据导入只读执行并可重复运行。
- iOS 可通过 Files 选择迁移目录，或接收由 Mac/Finder/Xcode 预先放入应用沙箱的迁移包；两种方式复用同一只读、幂等、逐记录校验导入器。
- 原生正式版通过验收前不得删除旧应用源代码或部署能力。
- 完成切换后仍保留旧数据导入能力至少多个正式版本。

## 7. 体验原则

- macOS 和 iOS 使用一致的信息架构与视觉语言，但采用各自平台导航和输入方式。
- iOS 书库与愿望单优先把垂直空间留给内容列表；搜索按需展开，隐藏搜索条件不得继续影响列表结果。
- iOS 标签筛选默认收起，隐藏时保留已选条件并显示数量徽标；展开可清空筛选。工具条保留 44 pt 点击面积，支持滚动时收缩留白；书库年月行不得悬浮覆盖书目。
- 列表书名、作者和辅助信息保持单行，减少重复留白；完整内容在编辑页读取。底部阅读统计基于当前筛选与阅读档案，点击档案名可切换；认证账户在设置中退出并重新登录。
- 阅读进度长条在前台轻微明暗呼吸，不改变已读数、进度比例或布局；减少动态效果及后台时保持静止。同步指示灯只以颜色表达状态，不呼吸；不将本地工作集总数描述为未同步数量。
- 设置只保留必要操作及实时结果：账户身份/退出/管理员邀请码、同步状态与重试、iOS 阅读档案和价格记录；服务配置和迁移收纳到默认折叠的高级设置，不显示内部存储技术或迁移期解释文案。登录、注册只出现在正式认证门禁。
- 反馈应即时、连续并可打断。
- 动效从当前呈现状态开始；减少动态效果时改用淡入淡出或静态过渡。
- 优先使用系统控件、SF Symbols、Dynamic Type 和平台材料。
- 删除等可恢复操作优先提供撤销；不可恢复操作才要求确认。
- 扫码、保存、失败和冲突使用清晰但不过度的声音/触觉/视觉反馈。

## 8. 验收标准

- 功能对照矩阵中所有现有能力均实现或获得明确豁免。
- Electron 数据导入前后逐记录校验通过。
- macOS 和 iOS 可离线完成核心 CRUD，并在恢复网络后同步。
- 同一账户在两端创建、修改、删除后最终一致。
- iOS 真机扫码和 macOS 价格抓取完成真实环境验证。
- VoiceOver、键盘、Dynamic Type、深浅色和 Reduce Motion 通过检查。
- 服务端接口安全审计完成，高风险问题关闭。
