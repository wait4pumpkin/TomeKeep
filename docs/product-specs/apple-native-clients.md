# 产品规格：Apple 原生客户端

## 1. 产品方向

TomeKeep 的正式客户端面向 macOS 与 iOS。两端使用 SwiftUI 原生实现，共享领域、持久化、网络、同步和元数据能力，并根据桌面与手机的使用场景提供不同界面。

原生双端完整交付后，Electron 桌面端与 Web PWA 停止作为产品形态维护。未来出现非 Apple 平台需求时重新评估跨平台方案，不在当前原生架构中预埋 Web 容器。

## 2. 产品目标

- 保留现有书库、愿望单、多档案、阅读状态、标签、搜索、排序、封面和价格能力。
- 保证已有 Electron 本地数据与云端数据无损迁移。
- iOS 支持 ISBN 手输、粘贴、单次扫码和连续扫码。
- macOS 与 iOS 均在本机查询和关联第三方元数据。
- macOS 保留价格抓取、Ollama 匹配、登录墙和验证码恢复。
- 两端均支持离线使用和可靠云同步。
- 界面遵循各自平台习惯，而不是复刻旧 React UI。

## 3. 平台能力

### 3.1 共享能力

- 认证、注册、退出和会话恢复。
- 书库与愿望单 CRUD。
- 愿望单移入书库。
- 多档案与独立阅读状态。
- 标签、搜索、排序和筛选。
- ISBN 校验、规范化与语义展示。
- 新增书库或愿望时可从剪贴板识别豆瓣详情 URL、ISBN 或书名；macOS 可自动检查豆瓣 URL，iOS 只在用户明确点击导入后读取剪贴板。
- 豆瓣/OpenLibrary/isbnsearch 元数据瀑布流。
- 豆瓣标题/作者搜索和候选关联。
- 封面下载、校验、缓存、上传和修复。
- 本地优先、离线 outbox 和同步修复。
- 中英文、深浅色和无障碍。

### 3.2 iOS 专属

- 摄像头 ISBN 扫描。
- 单本与连续录入。
- 扫描框选、声音和克制触觉反馈。
- 触控优先导航、Sheet 和滑动操作。

### 3.3 macOS 专属

- 高密度书库管理。
- 菜单命令、键盘快捷键和多窗口。
- 京东、当当、中国图书网价格抓取。
- Ollama 本地匹配与算法回退。
- 零售商与元数据网站的可见登录/验证码窗口。
- 旧 Electron 数据导入。

## 4. 数据要求

- 本地数据库是交互的第一写入目标。
- 网络失败不能导致本地业务操作丢失。
- 同步项必须持久化，应用重启后可继续。
- 已登录时，应用在启动、回到前台和登录成功后自动同步；本地业务写入成功后请求一次可合并的后续同步，不要求用户手工搬运数据。
- 应用保持离线优先，不以登录页阻塞启动；未登录时主界面必须持续说明“数据仅保存在本机”并提供登录入口，避免把本地可用误解为已经完成云同步。
- 覆盖安装可以保留系统钥匙串会话，因此已登录设备不要求每次启动重新输入密码；每台设备仍必须使用同一个 TomeKeep 账户，Xcode/Apple ID 登录不等于 TomeKeep 登录。
- 同步请求必须串行执行；进行中的重复请求合并为一个后续同步周期，避免并发覆盖并保证同步期间产生的修改会继续上传。
- 设置页必须显示本次运行的同步中、最近成功结果或失败原因，并保留手动重试入口。
- 云端 ID 与本地 ID 必须稳定。
- 软删除和 tombstone 必须跨设备传播。
- 封面本地缓存损坏不能破坏书籍记录。
- 迁移不得改变标题、作者、ISBN、出版社、标签、时间、优先级、阅读状态、详情 URL、封面关联或价格含义。

## 5. 第三方数据要求

- 原生客户端不得调用 TomeKeep 元数据代理。
- 查询只在用户明确录入、关联或修复时发起。
- 摄像头帧不得持久化或上传。
- 第三方登录凭据不得由 TomeKeep 读取或传输。
- Cookie 仅存储在应用专用网站数据存储中。
- 查询失败必须允许用户手工完成录入。
- 第三方页面结构变化不得损坏本地已有数据。

## 6. 迁移要求

- 迁移期 Electron、PWA 和原生客户端同时保持可用，但不能共享写入同一个本地目录。
- 原生预览版使用独立 Bundle ID 和数据目录。
- Electron 数据导入只读执行并可重复运行。
- iOS 可通过 Files 选择迁移目录，或接收由 Mac/Finder/Xcode 预先放入应用沙箱的迁移包；两种方式复用同一只读、幂等、逐记录校验导入器。
- 原生正式版通过验收前不得删除旧应用源代码或部署能力。
- 完成切换后仍保留旧数据导入能力至少多个正式版本。

## 7. 体验原则

- macOS 和 iOS 使用一致的信息架构与视觉语言，但采用各自平台导航和输入方式。
- iOS 书库与愿望单优先把垂直空间留给内容列表；搜索按需展开，隐藏搜索条件不得继续影响列表结果。
- 反馈应即时、连续并可打断。
- 动效从当前呈现状态开始；减少动态效果时改用淡入淡出或静态过渡。
- 优先使用系统控件、SF Symbols、Dynamic Type 和平台材料。
- 删除等可恢复操作优先提供撤销；不可恢复操作才要求确认。
- 扫码、保存、失败和冲突使用清晰但不过度的声音/触觉/视觉反馈。

## 8. 验收标准

- 功能对照矩阵中所有现有能力均实现或获得明确豁免。
- Electron 数据导入前后逐记录校验通过。
- macOS 和 iOS 可离线完成核心 CRUD，并在恢复网络后同步。
- 同一账户在两端创建、修改、删除后最终一致。
- iOS 真机扫码和 macOS 价格抓取完成真实环境验证。
- VoiceOver、键盘、Dynamic Type、深浅色和 Reduce Motion 通过检查。
- 服务端接口安全审计完成，高风险问题关闭。
